# 0001. PS1 렌더 파이프라인

- 상태: 채택
- 날짜: 2026-11-17
- 갱신: 2026-11-17 렌더타깃 320x240 → 240x320(세로) 확정

## 배경

[GDD §제품](../GDD.md#제품)은 PS1 레트로 그래픽을 요구한다: Three.js, 240x320(세로) 렌더타깃 nearest 업스케일, 버텍스 스내핑, affine 텍스처, 4bit 디더 + 15bit 컬러 양자화, 로우폴리, 64px 이하 절차 텍스처, 외부 에셋 금지. 대상은 모바일 브라우저 PWA다.

## 결정 기준

1. GDD 사양을 빠짐없이 재현한다.
2. 중저가 모바일에서 60fps를 유지한다.
3. 의존성을 three 하나로 유지한다(라이브러리 추가는 합의 대상).
4. `render.snapshot` 도구로 결과를 결정적으로 캡처할 수 있다.

## 검토한 대안

| 대안 | 장점 | 단점 |
| --- | --- | --- |
| A. 원본 해상도로 렌더 후 CSS `image-rendering: pixelated` 축소 | 가장 단순 | 렌더 비용이 줄지 않음. 디더·양자화를 픽셀 단위로 맞출 수 없음 |
| B. postprocessing 등 후처리 라이브러리 | 패스 구성이 편함 | 의존성 추가. 필요한 효과(스내핑·affine)는 어차피 머티리얼 쪽이라 이득이 작음 |
| C. 저해상도 렌더타깃 + 커스텀 셰이더 + 단일 후처리 패스 | 사양을 직접 제어, 픽셀 수가 적어 빠름, 의존성 없음 | 셰이더를 직접 관리 |

## 결정

C를 채택한다.

1. 씬을 240x320(가로x세로, 세로 화면) `WebGLRenderTarget`(`NearestFilter`, 안티앨리어싱 끔)에 렌더한다.
2. 버텍스 스내핑·affine 텍스처는 머티리얼 버텍스 셰이더에서 처리한다. 클립 좌표를 렌더타깃 해상도 격자에 스냅하고, UV를 원근 보정 없이(`w` 곱셈 후 프래그먼트에서 나눔) 보간한다. 공통 머티리얼 팩토리 하나에 모은다.
3. 풀스크린 쿼드 패스 하나에서 4x4 Bayer 디더(4bit) 후 RGB555(15bit) 양자화를 하고, 캔버스로 nearest 업스케일한다.
4. 텍스처는 코드로 만든 64px 이하 `DataTexture`(`NearestFilter`, 밉맵 없음)만 쓴다.
5. 렌더러 `pixelRatio`는 1로 고정한다. 업스케일 배율은 캔버스 CSS 크기로 정한다.

## 영향

- render 모듈은 공통 PS1 머티리얼과 후처리 패스를 소유한다. 다른 모듈은 이 결정을 알 필요가 없다.
- 스냅샷은 렌더타깃 해상도 기준이라 기기 해상도와 무관하게 비교 가능하다.
- 렌더타깃은 세로 화면에 맞춰 240x320(가로x세로)이다. 2026-11-17 사용자 합의로 정했다. GDD 수치라 이후 변경도 먼저 합의 대상이다.

## 재검토 조건

- 대상 기기에서 60fps를 못 지킬 때.
- GDD 그래픽 사양이 바뀔 때.
- 셰이더 패스가 3개 이상으로 늘어 라이브러리 도입 이득이 생길 때.
