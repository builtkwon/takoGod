# 리뷰

## 리뷰 종류

| 종류 | 누가 | 내용 |
| --- | --- | --- |
| 자체 리뷰 | 작업자 | 아래 체크 5항목으로 자기 변경을 본다 |
| 독립 리뷰 | reviewer 에이전트 | 영수증·도구 로그 대조, 테스트·경계 재실행, 체크 5항목 |
| 반박 검토 | 맥락 없는 검토자 | 판정 목록과 근거 파일만 받아 반박한다 |

- 금지: 테스트 통과만으로 리뷰를 대신한다.

## 언제

독립 리뷰를 추가하는 조건:

- 점수·별점·평균 정확성
- contracts 변경
- sessionStorage 키·형식
- 공통 유틸·빌드·PWA 설정

- 기본: 조건 해당 여부가 불분명하면 추가한다.
- 필수: 작업 시작 시 독립 리뷰 필요 여부와 근거를 한 줄로 밝힌다.
- 기본: 반박 검토는 사용자 결정 표를 올리기 직전과 단계 전환 직전에 한다.

## 체크 5항목

1. 요청 누락
2. 무관한 변경
3. 경계·contracts 준수([overview.md](../architecture/overview.md))
4. 정상·실패·경계값 테스트
5. 코드·문서 일치

지적 분류:

| 분류 | 처리 |
| --- | --- |
| 필수 수정 | 완료 전 수정 |
| 합의 필요 | 사용자에게 올림 |
| 선택 개선 | 완료를 막지 않음 |

## 증거

- 필수: 완료 주장은 실행한 도구와 종료코드로 뒷받침한다.
- 필수: 종료코드를 직접 읽지 못했으면 "미확인"으로 쓰고, 검토자나 지시자가 도구를 다시 실행한다.
- 금지: 출력 모양만 보고 통과로 단정한다.

## 영수증 표기

- 필수: 단계를 수행했으면 완료로 쓴다. 스킬 단계가 "고른다"처럼 기존 것을 쓰는 선택지여도 수행이다.
- 필수: 목표 미달·실패로 끝난 판정 단계는 `skip=Sn(사유)`로 쓰고 결과를 보고에 적는다.
- 형식은 [commits.md](commits.md#스킬-영수증).

## 대화 한도

- 필수: 지시자와 작업자의 왕복(지시 1 + 보고 1 = 1회)은 작업 하나당 2회까지.
- 필수: 2회째 보고에도 남은 쟁점은 토론하지 않고 사용자 결정으로 올린다.
- 자동 수정 3회 한도는 별도다 → [ai-execution.md](ai-execution.md#자동-수정-한도).
